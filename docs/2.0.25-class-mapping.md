# 2.0.25 类名映射与 Hook 说明

## 背景

2.0.25 使用 **SecShell** 加固，真实 DEX 通过 `InMemoryDexClassLoader` 加载。R8 将原 `com.bxkj.student.v2.common.utils.safe.*` 安全类重命名到**默认包**，类名变成 `ce`、`cj4` 等，旧版 FuckTSN 的 `safe.*` Hook 全部失效。

## 映射表

| 2.0.18 旧类 | 功能 | 2.0.25 新类 | Hook 方法 | 返回值 |
|---|---|---|---|---|
| `com.bxkj.student.v2.common.utils.safe.c` | Debug 检测 | `yj0` | `d()` | `false` |
| `...safe.d` | 模拟器检测 | `tz0` | `a()` | `false` |
| `...safe.f` | Hook 检测 | `rp1` | `a()` / `b()` / `c()` | `false` |
| `...safe.g` | Root 检测 | `cj4` | `d()` | `false` |
| `...safe.h` | TracerPid | `b15` | `a()` | `false` |
| — | 启动总控 | `ce` | `b()` / `a()` | 空实现 |
| — | 签名包装 | `a12` | `c(Context)` | `true` |
| `Transform` | 原生签名 | `com.google.android.datatransport.Transform` | `d(Context)` | `true` |

## 启动检测链

```text
App.onCreate
  → ce.b()
    → yj0.d()        Debugger / 22 端口 / debuggable
    → SafeGuardThread 每 100ms 检查 Debugger + b15.a()
    → tz0.a()        模拟器
    → rp1.c()        frida-server 文件 / XposedBridge
    → b15.a()        TracerPid
    → cj4.d()        Root
    → a12.c()        → Transform.d() 原生签名
  任一命中 → System.exit(0)
```

## 加载策略

1. Hook `ClassLoader.loadClass(String)` 与 `loadClass(String, boolean)`；
2. 在 `com.bxkj.student.App.onCreate()` 前主动 `XposedHelpers.findClass` 加载 `ce/cj4/tz0/rp1/b15/yj0/a12/Transform`，避免竞态；
3. 使用线程安全集合记录已 Hook 的类，避免多线程重复 Hook。

## 签名处理

- `a12.c(Context)` 是 Java 包装，Hook 返回 `true`。
- `Transform.d(Context)` 是 native 方法，LSPosed 也可以 Hook。
- 不修改 `Transform` 的签名/加密方法（`v/u/s/t/a/x/r/w`），正常网络请求仍使用原生逻辑。

## 部署要求

1. LSPosed 中启用模块，并勾选 `com.bxkj.student`；
2. 把体适能从 Magisk DenyList 移出，否则 LSPosed 无法注入；
3. 删除 `/data/local/tmp/frida-server`；
4. 重启体适能。

## 限制

- 类名由 R8 生成，后续版本可能再次变化；
- `hookProcessExit()` 会拦截进程内正常 `System.exit`，可按需移除；
- 仅用于学习交流和安全研究。
